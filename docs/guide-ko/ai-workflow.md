# AI 채팅으로 강의 슬라이드 쓰기

이 안내는 지금 쓰시는 AI 채팅(ChatGPT, Claude, Gemini 등 무엇이든)으로 MARCO 강의 덱을 만드는 방법입니다. 핵심은 하나입니다. **AI에게 HTML 파일을 통째로 받지 않고, 슬라이드 내용만 짧은 글(MARCO 소스)로 받습니다.** 디자인·글꼴·아이콘·발표 기능은 `marco build`가 붙여 줍니다.

## 준비물

- **작성 안내 한 파일**: `packages/ai/dist/kit/MARCO-작성-안내.md`. 채팅을 새로 열 때마다 한 번 붙여 넣습니다. 규칙, 컴포넌트 치트시트(글자 수 한도와 슬라이드 높이 어림 포함), 해설 문법, 문체 가이드, 점검 목록, 3주차·5주차 덱에서 옮긴 예시(표지, 체인·카드, 표, 비교·판정, 타임라인·알약, 해설)가 들어 있습니다.
- **작업별 요청문**: 같은 폴더의 `10-개요.md`, `20-슬라이드.md`, `30-해설.md`, `40-수정.md`, `50-검토.md`. `{{…}}` 칸만 채워서 붙여 넣습니다.
- **강의 소스 파일**: `lecture.marco.md`. 맨 위 front matter에 제목·과목·주차·강의 시간·참고 출처를 적어 둡니다.

```yaml
---
title: 6주차 · IDS/IPS
course: 보안시스템 운영 및 활용
week: 6
theme: cau-navy
duration: 150
refs:
  S01: { title: '출처 제목', url: 'https://…' } # 실제 제목과 주소를 적는다
---
```

AI는 출처를 이 목록의 id(`S01`)로만 인용하고, URL을 지어내지 않습니다. 목록에 없는 출처가 필요하면 `TODO: 출처 필요 — …`를 남깁니다.

## 단계별 흐름

### 1. 새 채팅에 작성 안내 붙여 넣기

`MARCO-작성-안내.md` 전체를 붙여 넣으면 AI가 "준비됨"이라고만 답합니다. 이후 이 채팅의 모든 답은 MARCO 소스로 옵니다.

### 2. 개요 받기

`10-개요.md`를 열어 과목·주차·주제·강의 시간·수강생·꼭 다룰 내용을 채워 붙여 넣습니다. 30–45줄짜리 개요가 옵니다.

```
01 | 표지 | 침입 탐지와 차단 | 오늘 다룰 질문을 연다 | 2
05 | 1부 | 탐지 원리 | 무엇을 보고 이상하다고 판단하는가 | 0.5
06 | 1부 · 시그니처 | 시그니처는 아는 공격만 찾는다 | 규칙 기반 탐지의 강점과 한계 | 3
```

한 줄이 슬라이드 한 장입니다(번호 · 태그 · 제목 · 한 줄 의도 · 분). 태그가 `1부`처럼 부 이름뿐이면 구분 슬라이드, `표지`·`마무리`·`참고 자료`는 각각 표지·인용·참고 자료 슬라이드가 됩니다. 이 단계에서 제목과 시간 배분을 충분히 고쳐 두세요. 가장 싸게 방향을 바꿀 수 있는 곳입니다. 개요는 `outline.txt`로 저장합니다.

### 3. 슬라이드 본문 받기 (6장씩)

`20-슬라이드.md`에 개요, 출처 id 목록, 범위(`01–06`)를 채워 붙여 넣습니다. 받은 답(코드 펜스 안쪽)을 `lecture.marco.md` 맨 아래에 붙입니다. 같은 채팅에서는 다음부터 "이어서 07–12번"이라고만 쓰면 됩니다.

한 번에 6장 정도가 좋습니다. 답이 짧아 잘리지 않고, 마음에 안 들면 그 6장만 다시 받으면 됩니다.

### 4. 빌드하고 확인하기

```
marco build
marco lint
```

`marco build`가 지금 쓰시는 것과 같은 단일 HTML 파일을 만듭니다. `marco lint`는 글자 수 초과, 없는 출처, 시간 합계 같은 문제를 슬라이드별로 알려 줍니다.

### 5. 린트가 문제를 알릴 때 붙여 넣을 것

`40-수정.md`에 **그 슬라이드 한 장**과 **그 슬라이드의 린트 줄**만 붙여 넣습니다. 덱 전체를 붙이지 않습니다. 돌아온 슬라이드로 원래 슬라이드를 통째로 바꿉니다.

| 린트 코드                           | 뜻                               | 붙여 넣을 것                                                           |
| ----------------------------------- | -------------------------------- | ---------------------------------------------------------------------- |
| `budget.cards.body` 같은 `budget.*` | 글자 수·항목 수 초과             | `40-수정.md` + 슬라이드 + 린트 줄. 요청 칸은 비워도 됩니다             |
| `budget.slide.dense`                | 본문이 화면 높이를 넘칠 듯함     | `40-수정.md` + 슬라이드 + 린트 줄. "블록을 줄이거나 두 장으로 나눈다"  |
| `table.ragged`                      | 표의 칸 수가 행마다 다름         | `40-수정.md` + 슬라이드 + 린트 줄                                      |
| `icon.unknown`                      | 없는 아이콘 이름(빌드가 알림)    | `40-수정.md` + 슬라이드 + 경고 줄. 아이콘 없이도 표시는 됩니다         |
| `ref.missing`                       | front matter에 없는 출처 id      | front matter에 출처를 추가하거나, `40-수정.md`로 "refs에서 S99를 뺀다" |
| `asset.missing`, `video.missing`    | 없는 이미지·영상                 | 파일을 `assets/`에 넣고 front matter에 등록                            |
| `note.marker.unknown`               | 해설 표시 오타(`[대사]` 등)      | `40-수정.md` + 슬라이드 + 린트 줄                                      |
| `note.cues.over`, `note.cue.long`   | 해설 큐가 너무 많거나 김         | `40-수정.md`로 "해설을 줄인다"                                         |
| `slide.id.duplicate`                | 슬라이드 id 중복                 | 직접 `# slide id=…`의 id 하나를 바꿉니다                               |
| `time.total`                        | `[시간]` 합계가 강의 시간과 다름 | 개요의 분 배분을 먼저 고친 뒤 해당 슬라이드만 수정                     |
| `content.todo` (정보)               | AI가 남긴 `TODO:` 확인 요청      | AI에게 보내지 않습니다. 사실을 확인해 직접 채웁니다                    |
| `format.*`                          | 문법 오류(`:::` 짝 등)           | `40-수정.md` + 슬라이드 + 오류 줄                                      |

여러 장을 한꺼번에 고치고 싶으면 슬라이드를 3–4장까지 붙여도 되지만, 한 장씩이 가장 정확하고 저렴합니다. AI가 방금 준 답을 스스로 다시 보게 하려면 `50-검토.md`를 붙여 넣으세요.

### 6. 해설(강의 대본) 받기

해설은 본문과 따로 받습니다. `30-해설.md`에 슬라이드 1–4장과 시간(`2.5분 · 10:00 – 12:30`)을 채워 붙여 넣으면, 5주차 대본과 같은 형식이 옵니다.

```
## note
[시간] 2.5분 · 10:00 – 12:30
[화면] 왼쪽 팩트 표, 오른쪽 빨간 CVE 카드, 아래 공격 체인 4단계.
[대사] 좋은 수사관은 추리보다 사실부터 모읍니다. …
[주목] @cisa-facts-b1 왼쪽 표 4행을 위에서부터 짚는다.
[발문] 이 네 단계 중 방화벽 룰이 직접 관여하는 단계는 어디일까요? | 10초
[전환] 다음 슬라이드에서 규칙 순서를 봅니다.
```

받은 `## note` 부분을 해당 슬라이드의 맨 끝에 붙입니다. 여러 장을 한꺼번에 받으면 장마다 `# slide …` 머리 줄이 붙어 오므로 어느 슬라이드 것인지 알 수 있습니다. 해설에 `[시간]`이 있으면 그 슬라이드의 `time:` 줄은 지웁니다. 남겨 두면 `time:` 값이 우선하고 경고가 하나 나옵니다(자동화 명령은 알아서 지웁니다). 분량은 아래 "해설 분량 고르기"를 보세요.

#### 해설 분량 고르기: 1분에 350자와 900자

해설 분량은 슬라이드의 `[시간]` 1분마다 몇 자를 쓰느냐로 정합니다. 두 가지 기준이 있습니다.

| 기준                 | 1분당    | 3분짜리 슬라이드            | 성격                                          |
| -------------------- | -------- | --------------------------- | --------------------------------------------- |
| 기본(말하는 속도)    | 약 350자 | 약 1,050자, `[대사]` 3–7개  | 그 시간 안에 실제로 소리 내어 말할 수 있는 양 |
| 5주차식(풍부한 대본) | 약 900자 | 약 2,700자, `[대사]` 7–18개 | 배경 설명·비유·예상 질문까지 담은 읽을거리    |

900자는 5주차 강사용 덱에서 잰 값입니다. 43장 모두에 `[시간]`이 있고 합계는 138분인데, `[대사]`만 약 12만 2천 자로 1분에 약 880자, `[예상답변]`까지 더하면 1분에 약 1,000자입니다. 말하는 속도로는 138분 수업에 약 4만 8천 자(1분에 350자)밖에 말할 수 없으니, 5주차 대본은 실제로 말하는 양의 약 2.5배를 담은 참고용 대본입니다.

고르는 법

- **350자(기본)**: 대본을 거의 그대로 읽거나 녹화·내레이션으로 쓸 때, `[시간]` 안에 반드시 끝나야 할 때, 처음 만드는 덱이라 빨리 초안을 보고 싶을 때. 받는 양이 적어 비용과 검토 시간도 가장 적습니다.
- **900자(5주차식)**: 수업 중에는 골라 말하고, 해설을 유인물 인쇄(`Ctrl+Shift+P`)나 조교·대리 강의자용 자료, 학생 복습 자료로도 쓸 때. 한 번 만든 대본을 여러 학기 다듬어 쓸 과목에 알맞습니다. AI가 쓰는 양과 비용은 약 2.5배입니다.
- 섞어 써도 됩니다. 핵심 개념 슬라이드만 900자로 받고 나머지는 350자로 두는 식입니다.

바꾸는 법: 채팅에서는 `30-해설.md`의 추가 요청 칸에 "분량은 1분에 약 900자로 한다"라고 씁니다. 자동화 명령은 `marco ai notes --slides 1-43 --cpm 900`입니다(기본값 350).

주의: 900자 기준에서는 큐가 슬라이드당 30개 한도(`note.cues.over`)를 넘기 쉽습니다. 5주차 덱은 43장 중 15장이 넘는데, `[주목]`·`[조작]`을 잘게 나눈 탓에 3분짜리 슬라이드에서도 넘습니다. 그런 슬라이드는 짧은 큐를 합치거나, 두 장으로 나누거나, 그 슬라이드만 350자로 받으세요. `[대사]` 하나는 600자(`note.cue.long`)를 넘지 않게 나뉘어 옵니다.

### 7. 배포

```
marco build --edition instructor   # 해설 포함 (강사용)
marco build --edition student      # 해설 없음 (학생용)
```

## 잘 되지 않을 때

- **AI가 HTML이나 설명을 섞어 답할 때**: "규칙 1–2를 지켜 MARCO 소스만, 코드 펜스 하나로 다시"라고 답합니다.
- **답이 중간에 끊겼을 때**: "이어서"라고 쓰고, 두 답을 이어 붙입니다.
- **채팅이 길어져 규칙을 잊는 것 같을 때**: 새 채팅을 열고 작성 안내를 다시 붙여 넣습니다. 개요는 그대로 다시 쓰면 됩니다.
- **`TODO:`가 보일 때**: AI가 확신하지 못한 사실입니다. 파일에서 `TODO`를 찾아 직접 확인해 채웁니다.

## 자동화(선택)

API 키가 있으면 같은 요청문을 명령 하나로 보낼 수 있습니다(명령 이름은 `marco ai --help` 기준).

```
marco ai outline "6주차 · IDS/IPS"
marco ai slides --batch 6
marco ai notes --slides 1-43
marco ai revise 12 "표를 3열로 줄이고 예시를 하나 추가"
```

API 없이 채팅창을 쓰면서도 파일 정리만 맡기고 싶다면 수동 모드(`--provider manual`)를 씁니다. 명령이 `.marco/ai/` 폴더에 요청문 파일을 만들고, 채팅 답을 짝이 되는 `.reply.md` 파일에 저장하면 이어서 진행합니다. 해설 붙이기와 슬라이드 교체는 명령이 알아서 합니다.

## 얼마나 아껴지나

지금까지는 덱을 만들거나 고칠 때마다 AI가 5–10 MB짜리 HTML 전체(엔진, 글꼴, 아이콘 포함)를 다시 써야 했습니다. 이제 AI는 내용만 씁니다.

- **작성 안내**는 약 1만 4천 자(예시를 빼면 약 1만 자, 대략 5천–6천 토큰, 글자 수 ÷ 2.5로 어림)이고, 채팅마다 한 번만 붙입니다. API로 쓰면 이 부분은 매번 똑같아서 제공사의 프롬프트 캐시가 적용됩니다.
- **새 덱 하나**: AI가 써야 하는 분량이 5–10배 줄어듭니다. 5주차 규모(43장, 대본 포함)라도 한 번에 몇천 토큰씩 나누어 받으므로 중간에 한도에 걸리지 않습니다. 대본 없는 학생용은 그보다 훨씬 적습니다.
- **슬라이드 한 장 수정**: 덱 전체를 다시 받던 것이 그 한 장(몇천 토큰)으로 줄어, 50–100배 절감됩니다.
