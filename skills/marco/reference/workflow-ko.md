# MARCO 작업 흐름 (에이전트용 한국어 요약)

`SKILL.md`의 작업 흐름을 한국어로 옮긴 것입니다. 교수님이나 조교에게 에이전트가 무엇을 하는지
설명할 때 씁니다. 규칙은 채팅용 작성 안내(`marco ai kit --print`)와 같습니다. 다만 채팅용 규칙
중 "답은 코드 펜스 하나", "'준비됨'이라고만 답한다"는 파일을 직접 고치는 에이전트에게는 해당하지
않습니다.

## 한눈에 보기

```
형식 익히기 → marco new(또는 기존 원고 열기) → 개요 → 슬라이드 6장씩 작성
  → marco build → 린트 읽기 → 표시된 슬라이드만 고치기 → (요청 시) 해설 → (요청 시) 학생용·PDF
```

## 단계

1. **형식 익히기.** `reference/format.md`(슬라이드 유형·필드·블록·글자 예산·높이)를 먼저 읽는다.
   해설을 쓸 때는 `reference/notes.md`도 읽는다. MCP 도구가 있으면 `marco_kit`(section
   `cheatsheet`)을 불러도 된다. 한 장만 고칠 때는 `marco_replace_slide`, 넣기 전 점검은
   `marco_check_slide`.
2. **새 강의 만들기 또는 원고 열기.**
   `marco new week06 --title "6주차 · IDS/IPS" --course "보안시스템 운영 및 활용" --week 6`
   (5주차 모양은 `--theme cau-navy`). `week06/lecture.marco.md`와 `week06/assets/`가 생긴다.
   연습용 슬라이드 세 장은 지운다. 머리말의 `presenter: 담당 교수`, `duration: 20`, 예시 출처
   `S01`(`https://example.com`), 예시 용어 `IAM`은 자리표시자이므로 실제 값으로 바꾸거나 지운다.
   출처(`refs`)는 교수님이 준 제목·주소, 또는 직접 열어 확인한 것만 적는다.
3. **개요.** 새 덱이면 먼저 `번호 | 태그 | 제목 | 한 줄 의도 | 분` 한 줄에 한 장으로 개요를 만든다.
   전체 강의는 30–45장: 표지 → 도입(사례·질문) → 학습 안내 → 1부·2부(·3부, 각 부는 구분
   슬라이드로 시작해 8–15장) → 개념 정리 → 마무리 → 참고 자료. 한 장에 주장 하나, 분은 0.5
   단위, 합계는 `duration`과 같게. 40장을 쓰기 전에 개요를 교수님께 보여 준다.
4. **슬라이드 작성.** 6장 정도씩 머리말 아래에 이어 쓴다. 개요 한 줄 = `# slide` 하나, 개요의
   태그·제목을 그대로 쓴다. 본문 슬라이드는 `# slide id=영문-소문자-id`(2–4단어), `tag`,
   `title`, `time`, 필요하면 `question`·`refs`. 본문 블록은 2–3개(시각 블록 하나 +
   `takeaway`·`callout`·`verdict` 하나). 쓰면서 글자 수와 높이 합을 확인한다.
5. **빌드.** `marco build week06/lecture.marco.md` → `week06/lecture.html`. 형식 오류
   (`format.*`)가 있으면 `✗ 빌드 중단`과 함께 HTML을 만들지 않는다.
6. **린트를 읽고 표시된 슬라이드만 고친다.** 다시 빌드해 출력 어디에도 `오류`·`경고` 줄이 없을
   때까지 반복한다. 요약 줄 `린트 · 오류 0 · 경고 0`만 보면 안 된다: 그 위의
   `파일:줄 경고 [format.…]` 줄은 요약에 세지 않고, `marco build`는 `경고 [icon.unknown]`을 요약
   아래에 따로 찍는다. `정보 content.todo`(남긴 `TODO:`)는 교수님이 확인할 몫이므로 그대로 둔다.
7. **해설**은 요청받았을 때만, 본문과 따로 쓴다(`reference/notes.md`).
8. **전달.** 요청한 것만: HTML 경로, 학생용
   (`marco build <원고> --edition student -o <이름>-student.html`), PDF(`marco pdf <원고>`,
   유인물은 `--mode handout`). 마지막에 바꾼 슬라이드, 린트 요약, 남은 `TODO:` 목록을 보고한다.

**한 장 고치기.** "12번 슬라이드"는 원고의 12번째 `# slide`(머리 줄을 센다) 또는 이름을 댄
`id=`의 슬라이드다. 그 슬라이드의 요청한 부분만 바꾼다. 요청이 없으면 머리 줄(id), `tag`,
`refs`, `## note`는 그대로 둔다. 블록 순서가 바뀌면 해설의 `@id-b번호`도 맞춘다. 다른 슬라이드는
다시 쓰거나 요약하지 않는다.

## 지킬 것

1. **MARCO 소스만** 쓴다. HTML·CSS·JavaScript, `# slide raw`, `:::html`은 쓰지 않는다. 빌드된
   `.html`을 고치지 않는다.
2. **슬라이드 하나 = `# slide` 블록 하나.** `# slide`는 줄 맨 앞. 필드는 머리 줄 바로 아래, 빈 줄
   하나 뒤에 본문. 본문 소제목은 `###`만.
3. **글자 예산과 높이 예산을 지킨다.** 넘치면 줄이거나 합치거나 두 장으로 나눈다.
4. **해설은 `## note` 아래** 해설 문법으로, 요청받았을 때만.
5. **문체.** 슬라이드는 짧은 평서문(…다), 제목은 주장 한 문장(34자 이하). "~합니다", "매우",
   "다양한", 느낌표, 이모지는 쓰지 않는다. 해설 `[대사]`는 강의하는 말투(…예요, …죠).
6. **출처는 id로만**(`refs: [S13, W06]`). URL, 영상 id, 이미지 경로, 수치, 법 조항, 제품
   모델명, 날짜를 지어내지 않는다.
7. **확실하지 않으면 그 자리에 `TODO:`**: `TODO: 확인할 내용`, `TODO: 출처 필요 — 무엇`,
   `TODO: 이미지 — 무엇`. 교수님은 `marco lint --verbose`로 모아 본다.
8. **요청받은 범위만** 고친다. 슬라이드 id는 바꾸지 않는다.

## 린트를 읽는 법

```
  card-steps #4 카드 인식, 허용, 문 열림, 사람 통과는 다른 단계다 (lecture.marco.md:40)
    경고 budget.cards.body  cards[1].body: 104자 (허용 90자)
    오류 ref.missing  refs에 없는 참고 출처: S99
린트 · 오류 1 · 경고 1 · 정보 1
```

`슬라이드 id #순서 제목 (원고:줄)` 아래에 `수준 코드  메시지`가 나온다. 수준은 오류·경고·정보.
메시지 속 번호는 0부터(`cards[1]` = 둘째 카드), `#2` 같은 블록 번호는 1부터 센다. 코드별 뜻과
고치는 법은 `reference/lint-codes.md`에 있다.

메시지가 나오지 않는 실수 네 가지는 직접 확인한다: 표의 행이 머리글보다 칸이 많음(넘친 칸은
사라진다), 필드 사이의 빈 줄(뒤의 필드가 본문 문단이 된다), 줄 형식 앞의 `- `(한 항목의 글이
된다), 없는 블록을 가리키는 해설의 `@대상`.
